Motion and loading

Based on Emil Kowalski's animation rules (emilkowalski/skills: animate, emil-design-eng, mobile-native) and NN/g skeleton screen research.

When to show what while loading

PWA cold start onlySplash

Installed app opened from the home screen. Logo in, max 600ms, then the page. Never in a browser tab, never on navigation.

First page loadNothing

Server rendered HTML arrives complete. No spinner, no skeleton. Images use their blur placeholder.

Navigation under 300msNothing

Cached or fast loaders. Showing a loader would only flash.

Navigation 300ms to 1sTop progress bar

Thin terracotta bar at the top, page stays interactive. Router pending state.

Data heavy route over 1sSkeleton

Shop grid, product, orders, admin tables. Same layout as the real page, so nothing jumps. Show after 300ms, keep at least 500ms.

User actionButton spinner

Place order, Save product, Make admin. Disable the button, keep the label, never block the whole page.

Cart changesOptimistic

Add, remove, quantity update instantly in local state. Toast confirms. Server reconciles on checkout.

Rules

  1. Animate transform and opacity only. Never width, height, top or margin.
  2. Never animate from scale(0). Start at 0.96 with opacity 0.
  3. Keyboard actions (/, Esc, arrow keys in search) never animate.
  4. No ease-in on UI. It makes the first frames feel slow.
  5. Hover effects live inside (hover: hover) and (pointer: fine), so taps never get stuck.
  6. prefers-reduced-motion keeps fades and colour, removes movement and the shimmer.
  7. Interruptible: use CSS transitions for state, keyframes only for one shot entrances.
  8. Numbers that change (cart subtotal) use NumberFlow, not a re-render flash.
